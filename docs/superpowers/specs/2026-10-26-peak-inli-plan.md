# Пик INLI — план реализации

Основа: [дизайн](2026-10-26-peak-inli-design.md). Код пишется шагами; каждый шаг — отдельный цикл «Твори» → тесты (красная фаза → зелёная) → проверка в браузере → коммит и пуш → отдельное «Твори» на PR и мерж. Новые функции пишутся рядом с существующими, по образцу заморозок и казино (`index.html` — один файл).

Точки подключения в коде (по состоянию `main` на 2026-10-26):
- вкладки: навигация `data-view` (рядом с `casino`), разделы `<section id="view-…">`, переключение — `switchView(v)`;
- состояние: `freshState()` (рядом с `casinoBets:[]`) и `migrate()` (рядом с проверками `state.casinoBets`); глобальные журналы лежат на верхнем уровне `state` (как `purchases`), а не в `YEAR_FIELDS`;
- баланс: `recalcPoints()` складывает замороженные журналы (`purchases`, `casinoBets` …); после изменения баланса вызываются `recalcPoints(); save(); renderXP();`;
- строки интерфейса: словари `I18N` на 5 языков (`T.ключ`), без запасного языка — ключ нужен во всех пяти;
- единица цены: `dailyUnit()`; приём «дни × dailyUnit в момент выплаты» как в магазине;
- `sw.js` кэширует любые GET-запросы сам (сеть сначала, кэш запасом), список `ASSETS` менять не нужно; файл вопросов появится в кэше после первой загрузки;
- тесты: `tests/load-app.js` (список экспортируемых функций), `node --test` в `tests/`, проверка в CI — `pr-checks.yml`.

## Шаг 1. Каркас: вкладка, состояние, чистая логика, лимит, выплата

Файлы: `index.html`, `tests/load-app.js`, `tests/peak-core.test.js`.

- Состояние `state.peak = {games:[], seen:[], active:null}`: `games` — завершённые игры `{id, year, month, date, reached, payoutDays, payoutInli, lifelines[], end}` (`end`: `walk`/`wrong`/`timeout`/`violation`/`interrupted`/`top`); `seen` — показанные id вопросов; `active` — незавершённая игра (если есть при загрузке → проигрыш, выплата 0).
- Миграция в `migrate()`; пустое значение в `freshState()`.
- Константы: `PEAK_PRIZE_DAYS` (лесенка B), `PEAK_SAFE=[5,10]`, `PEAK_GAMES_PER_MONTH=3`, `PEAK_SECONDS=120`.
- Чистые функции: `peakPrizeInli(level)` (дни × `dailyUnit()`), `peakPayoutOnWrong(level)` (несгораемая), `peakGamesThisMonth(year,month)`, `peakAttemptsLeft()`, `peakStartGame()` (списывает попытку сразу, создаёт `active`), `peakFinishGame(end, reached)` (пишет чек с замороженной суммой в `games`, чистит `active`, вызывает `recalcPoints()`), `peakDropInterrupted()` (на загрузке).
- `recalcPoints()`: добавить `pts+=(state.peak.games||[]).reduce((s,g)=>s+g.payoutInli,0)`.
- Достижение «Big Spender» и подобные не затрагиваются (выплаты в `purchases` не попадают).
- Вкладка: пункт навигации и пустой `<section id="view-peak">` с заголовком, остатком попыток и кнопкой «Тренировка»-заглушкой; строки на 5 языках.

Тесты (красные сначала): лесенка и несгораемые суммы; выплата при неверном ответе на уровнях 1–5, 6–10, 11–15; лимит 3 в календарный месяц и сброс в новом месяце; попытка списывается на старте; перезагрузка с `active` = проигрыш и 0; чек хранит замороженную сумму (смена весов привычек не меняет её); `recalcPoints()` прибавляет выплаты ровно один раз.

Готово, когда: все тесты зелёные, существующие тесты не сломаны, вкладка открывается и показывает «осталось N из 3» (проверка в Chromium).

## Шаг 2. Экран игры, подсказки, таймер, защита

Файлы: `index.html`, `tests/peak-game.test.js`, проверочный скрипт Playwright (не в репозиторий).

- Чистый движок игры (без DOM): состояние вопроса, `peakAnswer(i)` (верно/неверно/двойной шанс), `peakUseLifeline(kind)`: `5050` (убирает 2 неверных), `phone` (ответ и уверенность по уровню), `audience` (распределение), `double` (запрет с 50:50 на одном вопросе; сгорает при ответе в любом случае); `peakWalkAway()`; тайм-аут = неверный ответ; верхний приз при 15 верных.
- Выбор вопросов: 15 штук, по одному на уровень, не менее 8 категорий, не более 2 одной категории, подряд одинаковых нет, из непоказанных (`seen`; сброс, когда банк уровня исчерпан), случайный порядок вариантов.
- Экран по макету: верхняя панель, вопрос и варианты в шестигранниках, лесенка, подсказки, «Забрать», подтверждение «окончательный ответ», итог, экран нарушения.
- Защита: предстартовая проверка (видимость, фокус, полный экран через `requestFullscreen()` по кнопке, подтверждение «Не беспокоить»); во время игры `visibilitychange`, `blur`, опрос `document.hasFocus()` каждые ~500 мс, `fullscreenchange`, закрытие страницы → `peakFinishGame('violation', …)` с выплатой 0 и причиной на экране. Если Fullscreen API недоступен (iPhone) — игра с INLI не стартует, доступна «Тренировка».
- Таймер на `performance.now()` (устойчив к троттлингу), запрет выделения, копирования и контекстного меню на экране игры.

Тесты (юнит): 50:50 оставляет верный и один неверный; «Двойной шанс» — первая ошибка не завершает, вторая завершает, сгорает при верном и неверном; нельзя совместить с 50:50; подсказка один раз; тайм-аут = ошибка; выбор вопросов по правилам категорий; нет повторов до исчерпания. Браузер: старт заблокирован без полного экрана; скрытие вкладки, потеря фокуса и выход из полного экрана завершают игру с 0; нормальная игра до 3 вопросов; перезагрузка посреди игры = проигрыш.

Готово, когда: тесты и проверка в Chromium зелёные; на телефонной ширине экран читаем.

## Шаг 3. Оформление и звук

Файлы: `index.html` (знак, стили, синтез звука).
- Знак А (SVG) в заголовке вкладки, на старте и в итоге; значок вкладки. Стили и анимации по макету (появление вариантов с задержкой, раскрытие ответа).
- Синтез звука (Web Audio): напряжённый фон, окончательный ответ, верно, неверно, подсказка, тик последних 20 секунд, вершина, нарушение; включается только по действию пользователя; выключатель громкости, сохраняется локально.
- Проверка: нет ошибок в консоли, звуки запускаются; на слух оценивает владелец.

## Шаг 4. Банк вопросов

Файлы: `peak/questions.ru.json`, `peak/questions.en.json`, затем `es`, `zh`, `fr`; `tests/peak-bank.test.js`.
- Запись: `{id, level, category, q, options[4], correct, explanation}`; `id` и `correct` одинаковы во всех языках. Не менее 30 вопросов на каждый из 15 уровней (около 450 на язык), около 14 категорий, правила сложности и качества из дизайна.
- Загрузка только файла активного языка (`fetch`), запасной вариант при ошибке — «Тренировка» недоступна, сообщение; язык игры = язык интерфейса.
- Каждый факт проверяется минимум по двум независимым источникам; список источников хранится отдельным файлом заметок, не в банке. es, zh, fr помечаются бета до проверки носителями.
- Тест банка: схема, число на уровень, нет дублей текста и `id`, один верный индекс 0–3, длина вариантов, в es/zh/fr нет вопросов, которых нет в ru/en.
- Делается порциями (например, по 2–3 уровня за раунд), каждая порция проходит тест банка.

## Шаг 5. Режим «Тренировка» и полировка

- «Тренировка»: те же правила и подсказки, но без лимита, без защиты, без INLI и без записи в `games`/`seen`; доступна на телефонах.
- Экран «Разобрать вопросы» (вопросы игры с пояснениями), итоговая статистика месяца, доступность (фокус, контраст), `prefers-reduced-motion` для анимаций.
- README: строка о новой игре. Итоговая проверка: все тесты, браузерный прогон полной игры, телефонная ширина.

## Порядок выпуска и риски

- Игра видна пользователю только когда есть хотя бы ru-банк (шаг 4): до этого вкладка за флагом, чтобы в `main` не попала пустая игра.
- Допущения экономики (доли игроков, калибровка сложности) уточняются по реальной игре; ступени задаются одной константой.
- Не проверено заранее: поведение Fullscreen API на мобильных и в Safari, звук на слух, факты и переводы в банке.
- Вне этого плана: ИИ-аналитик, ИИ-бот-справочник, реальные призы.
